## 1. Apply migrations 0140, 0141, 0142 and 0143

**This is the only step that touches production member data.** Both are additive and idempotent, and
neither rewrites a row. Paste the whole block into the Supabase SQL editor.

```sql
-- 0140: a member can be PAUSED. Adds one value to the entitlements status CHECK.
alter table public.entitlements
  drop constraint if exists entitlements_status_check;

alter table public.entitlements
  add constraint entitlements_status_check
  check (status in ('active', 'trialing', 'past_due', 'paused', 'canceled', 'expired', 'revoked'));

comment on column public.entitlements.status is
  'Provider-normalized lifecycle. Only active and trialing grant access (isActiveEntitlementStatus). '
  'paused is a coach-granted break: no access to paid surfaces, her own records stay readable, '
  'expires_at holds the resume date.';

-- 0141: archive a program instead of deleting it.
alter table public.plans
  add column if not exists archived_at timestamptz;

create index if not exists idx_plans_company_active
  on public.plans (company_id, name_en)
  where archived_at is null;

comment on column public.plans.archived_at is
  'Set to hide a plan from the coach library and pickers. NEVER delete a plan: plan_assignments '
  'references it and a member may be mid-program. Archived plans still resolve by id everywhere '
  'they are already assigned.';
```

Verify — both rows should come back:

```sql
select column_name, data_type
from information_schema.columns
where table_schema = 'public' and table_name = 'plans' and column_name = 'archived_at';
```

### 1b. `0142_tenant_boundary.sql` — apply this one separately, and test it

Do **not** paste this one inline. Run the file as written
(`supabase/migrations/0142_tenant_boundary.sql`, 207 lines) — it replaces 21 RLS policies and the
comments in it are the reasoning for each.

**What it does.** 21 policies granted access on `public.is_coach()` alone, with no company
predicate, so a coach in company A could read every profile in company B and could read *and write*
company B's `form_responses` — which since the August sweep holds every member's weight,
circumferences, sleep, mood and her reason for starting. Not exploitable today, because there is one
company. Exploitable the day there is a second.

**Why it should change nothing today.** Only the `is_coach()` branch is narrowed; every
`= auth.uid()` branch is copied through untouched, so no member's access to her own data changes.
With one company, `company_id = auth_company_id()` is true for every row a coach can already see.
Only 3 files under `src/app/(app)/coach` use the RLS-bound client at all — 49 use the service
client, which bypasses RLS entirely.

**The one real change:** `webhook_events` has no company column (it is the Stripe idempotency
ledger), so its policy narrows from `is_coach()` to a new `is_operator()`. Coaches and assistant
coaches lose read access to raw Stripe event payloads.

**Verify — this is the step that matters, and it is a browser step, not a SQL one.** The migration
applying cleanly is not evidence anyone can still read anything.

1. Signed in as Stephanie (coach): open `/coach`, `/coach/clients`, `/coach/subscribers/[id]`,
   `/coach/intake`. All four must load **with data**, not empty states. An empty state here means
   `auth_company_id()` returned null and every coach read is being denied.
2. Signed in as a member: `/dashboard`, `/workouts`, `/progress`, `/you`. Her own rows must still
   be hers.
3. Confirm the helper resolves rather than returning null:
   ```sql
   select p.id, p.role, p.company_id from public.profiles p where p.role = 'coach';
   ```
   then, signed in as that user through the API, `select public.auth_company_id();` must equal that
   `company_id`.
4. `node .qa-visual/tenant-boundary-test.mjs` — static, no credentials, and it fails if any policy
   still grants on `is_coach()` without a company predicate. Run it before and after: before 0142
   exists it reports exactly 21.

**If step 1 comes back empty, revert immediately.** The previous policy definitions are in 0018,
0025, 0026, 0027, 0028, 0034, 0136 and 0139. Reverting restores the hole, which is survivable for as
long as there is one tenant; a locked-out coach console is not.

## 2. Pick the starter program, then set the env vars

I could not choose these: picking well means seeing her 40 programs, and blind pattern-matching on
plan names is the mistake that produced a wrong check-in importer earlier in this project.

Run this and pick one row:

```sql
select p.id,
       p.name_en,
       p.weeks,
       (select count(*) from sessions s where s.plan_id = p.id)         as days_built,
       (select count(*) from plan_assignments a where a.plan_id = p.id) as clients_on_it
from plans p
where p.company_id = 'c0ffee00-0000-4000-8000-000000000001'
  and p.archived_at is null
```

Choose a plan that has `days_built > 0` (an empty plan gives a new member a blank week) and that

## 5. Backfill the check-in assignment

Existing members never got the check-in that new members now receive at onboarding, so the biggest
button on their Today screen still opens an empty list. `scripts/backfill-checkin-assignments.mjs`
does this but needs `.env.local`; here it is as SQL so it does not.

Count first:

```sql
select count(*) as members_without_checkin
from profiles p
where p.company_id = 'c0ffee00-0000-4000-8000-000000000001'
  and p.role in ('subscriber', 'free')
  and not exists (
    select 1 from form_assignments a
    where a.profile_id = p.id
      and a.form_id = (
        select id from forms
        where company_id = 'c0ffee00-0000-4000-8000-000000000001'
          and type = 'check_in' and status = 'published'
        order by created_at asc limit 1
      )
  );
```

Then assign. Idempotent — `form_assignments` is unique on `(form_id, profile_id)`, so re-running
skips anyone who already has it and moves nobody's `assigned_at`:

```sql
insert into form_assignments (company_id, form_id, profile_id)
select 'c0ffee00-0000-4000-8000-000000000001',
       (select id from forms
        where company_id = 'c0ffee00-0000-4000-8000-000000000001'
          and type = 'check_in' and status = 'published'
        order by created_at asc limit 1),
       p.id
from profiles p
where p.company_id = 'c0ffee00-0000-4000-8000-000000000001'
  and p.role in ('subscriber', 'free')
on conflict (form_id, profile_id) do nothing;
```

The oldest published form is chosen deliberately, matching `src/lib/checkins/assign-default.ts`: an
established form is what a member should get, and a newly published one is as likely to be a one-off
as a new standard.
